# 0006. React frontend served by Spring Boot

Status: Accepted
Date: 2026-11-08

## Decision

- `frontend/`: React 19 + Vite 8 single-page app, HeroUI v3 components, TanStack Router (file routes, filters
  and tabs in the URL), TanStack Query (keys per area, a write invalidates its area), TanStack Form + zod,
  Tailwind 4, Biome, Yarn 4.
- The API client is generated by orval from the springdoc OpenAPI (`yarn api:gen`) as plain axios functions;
  the hooks and keys are written by hand. Controller method names are the operation ids, and an
  `OpenApiCustomizer` marks non-nullable Kotlin properties as required, so the generated types are exact.
- One origin: `frontend/build-to-resources.sh` builds `dist/` and copies it to `app/src/main/resources/static`
  (git-ignored); the Docker image does the same in a Node stage. `SpaForwardController` returns `index.html` for
  client routes; `/api`, Actuator and OpenAPI paths are left alone. In development Vite proxies `/api`.
- Session cookie (HttpOnly) and CSRF cookie: axios sends `XSRF-TOKEN` back as `X-XSRF-TOKEN` by default; the
  browser never sees a token. A 401 from the API sends the user to `/login?redirect=...`.
- Look: the Ambit Obsidian theme (obsidian and linen, champagne accent, Cormorant Garamond titles over Inter,
  mono table heads). Its palette is kept under `--obs-*` and feeds HeroUI's variables, so no hex colour appears
  in a component.

## Consequences

Plus: one deployable, no CORS, cookies as designed; the generated client follows the Kotlin types.
Minus: the jar grows by the built assets; a change of the API needs `yarn api:gen` with the stack running.
